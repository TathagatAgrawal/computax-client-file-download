1. Summary & recommendation

Use Meta's official WhatsApp Cloud API directly, with no middleman. ITR Fetch calls Meta's API over HTTPS from your computer, using only Python's standard library, so nothing new needs installing. Each PDF is sent as one utility template message with the PDF attached in the message header, which is allowed even when the client hasn't messaged you recently.

  • Phone numbers are already in your data. All 412 clients that have an ITR JSON file (FiledJson) have a MobileNo in it, all with country code 91. The app pre-fills that number, and you can edit it before sending.
  • Cost is tiny. A utility message to an Indian number costs about ₹0.115 + 18% GST ≈ ₹0.14 per PDF (third-party figure; confirm on Meta's rate card). Sending 6 PDFs to one client is about ₹0.81. The API itself is free.
  • Setup is the main effort. You need a Meta Business portfolio, a phone number registered on WhatsApp's business platform, a payment method, an access token, and one approved message template. It is done once, mostly in Meta's web dashboards, and template approval can take up to 24 hours.
  • Main limitation: the app can confirm that WhatsApp accepted a message, but not that it was delivered or read. Delivery reports only arrive via webhooks, which need a public internet address that a desktop app doesn't have (see section 4 and decision 5).

2. How WhatsApp's API works

The platform

The WhatsApp Business Platform is Meta's API for businesses. Its Cloud API is hosted by Meta: you send HTTPS requests to graph.facebook.com with an access token, and Meta delivers the messages. The older self-hosted “On-Premises API” is retired, so the Cloud API is the only official route. Businesses can use it directly or through a reseller (a “Business Solution Provider” such as Twilio, Gupshup, Interakt or AiSensy), which adds its own fees.

When you may message someone

Message typeWhen allowedWhat it can contain
Template message (marketing, utility, authentication)Any time, as long as the recipient has opted in to hear from you.Pre-approved wording with variables. The header can be a document (PDF), image, video or text.
Free-form (“service”) messageOnly within 24 hours of the client last messaging you (the “customer service window”).Any text or media, including documents.

Clients usually won't have messaged the firm in the last 24 hours, so sending files has to use a template. A template with a document header carries exactly one file, so each PDF is one message. An example of what the client sees:

PDF ITRV_109B_2024.pdf
1 page · 82 kB
Dear RAKESH SHARMA, please find attached your ITR-V acknowledgement for Assessment Year 2024.

– Sharma & Associates
11:42

Illustrative. The wording is fixed by the approved template; the client name, document type, year and firm name are variables.

Template categories

Meta classifies each template as marketing, utility or authentication, and the price depends on the category. Utility means a message about a specific transaction or account the customer is already involved in, which fits sending a client their own tax documents. Meta reviews the template and may reclassify it as marketing if the wording looks promotional, so the template must be plain and transactional.

Media rules (from Meta's docs)

  • Documents can be PDF, Word, Excel, PowerPoint or text files, up to 100 MB. ITR-V and Computation PDFs are far smaller.
  • Files are uploaded with POST /<phone-number-id>/media, which returns a media ID. The message then refers to that ID. Uploaded media and IDs expire after 30 days.
  • The file name the client sees can be set separately, so they would see ITRV_109B_2024.pdf.

3. One-time setup (done by the firm, outside ITR Fetch)

  1. Meta Business portfolio. Create one at business.facebook.com, or use an existing one, under the firm's legal name.
  2. Meta developer app. At developers.facebook.com, create an app of type “Business” and add the WhatsApp product. This creates a WhatsApp Business Account (WABA) and a free test number that can message up to 5 verified numbers. That is enough to try ITR Fetch before going live.
  3. Phone number. Add the number the firm will send from, verify it by SMS or a call, and set the display name, which Meta reviews. Two options (decision 1):
    • A dedicated new number (simplest). It must not be in use on any WhatsApp app.
    • The firm's existing WhatsApp Business app number, using Meta's “coexistence” feature, which lets the app and the API share one number. Onboarding is done through Meta's “Embedded Signup” flow, which is usually provided by a Meta partner. Third-party sources disagree on how chat history syncs between the two.
  4. Payment method. Add a card in Meta Business settings → WhatsApp accounts → Payment settings. Meta is moving Indian businesses to INR billing; it must be done by 31 Dec 2026 or messages stop on 1 Jan 2027.
  5. Permanent access token. In Business settings → System users, create a system user, give it the WhatsApp account, and generate a token with the whatsapp_business_messaging and whatsapp_business_management permissions. The token shown on the developer dashboard expires in 24 hours and is only for testing.
  6. Message template. In WhatsApp Manager → Message templates, create a Utility template with a Document header, for example: 
    Name:     itr_document            Category: Utility      Language: English
Header:   Document  (sample PDF uploaded for review)
Body:     Dear {{1}}, please find attached your {{2}} for Assessment Year {{3}}.
Footer:   {{firm name, fixed text}}
    Review can take up to 24 hours. ITR Fetch can also create the template via the API, but a document-header template needs its sample PDF uploaded through a separate “resumable upload” API. The dashboard is simpler for a one-off.
  7. Business verification (recommended, not required to start). New accounts can message 250 different people per 24 hours. Verifying the business, by uploading registration documents, raises this to 2,000, after which it grows automatically with good message quality.
  8. Enter the details into ITR Fetch: phone number ID, WhatsApp Business Account ID, access token and template name. The app tests the connection and the template status (screen W1).

ConcernHow it is handled
No dependenciesThe Graph API is plain HTTPS and JSON, so urllib is enough. The file upload needs a multipart/form-data body, which is about 20 lines to build by hand. I checked that the bundled Python reaches graph.facebook.com with valid certificates on macOS. Windows uses the system certificate store; this will be checked in the first Windows build.
InternetCopying files still works offline. Only sending needs internet, and if Meta can't be reached the app says so clearly.
Storing the token (a secret that can send messages as the firm)Stored in the OS's secure credential store: the macOS Keychain (via the built-in security command) or Windows Credential Manager (via ctypes). It is never written to settings.json and never sent to the browser page. The non-secret IDs (phone number ID, account ID, template name, firm name) go in settings.json next to the CompuTax path. This extends the earlier “only the CompuTax path is saved” rule, but it is needed so the setup isn't repeated (decision 4).
Delivery statusMeta reports sent / delivered / read / failed only by calling a webhook, a public HTTPS address. A desktop app behind a home or office router has none, and the API has no endpoint to poll for status. So:
  • The app shows “Accepted by WhatsApp” once Meta returns a message ID. Problems Meta catches straight away, such as a bad token, an unapproved template or an invalid number format, appear as errors at once.
  • Failures Meta finds later are not visible to the app, for example a number that isn't on WhatsApp. The client simply won't receive it. You can see these in WhatsApp Manager's insights.
  • A later add-on could be a tiny free cloud relay, such as a Cloudflare Worker, that receives webhooks and lets ITR Fetch fetch the statuses (decision 5).
Phone numbersRead from MobileNo and CountryCodeMobile in the client's latest FiledJson, the same file the name comes from, then shown and editable before sending. Numbers are normalised to 91XXXXXXXXXX. Edited numbers are not saved, in keeping with the no-persistence rule.
PrivacyOnly the selected PDFs and the client's name, document type and year leave the computer, sent directly to Meta. Nothing goes to any other server.

5. Sending flow & API calls

  1. The user selects a client and years as today, then clicks Send on WhatsApp… next to Copy files.
  2. A panel shows the number (pre-filled from FiledJson), the client's name as it will appear in the message, and a checklist of the PDFs that will be sent, one row per file and year.
  3. Send opens a confirmation summary (“Send 4 PDFs to +91 98xxx xxx21 (RAKESH SHARMA)?”). This is required because a sent message can't be recalled, and a wrong number would expose a client's tax documents to someone else.
  4. For each PDF, one at a time: 
    POST https://graph.facebook.com/v{N}/{PHONE_NUMBER_ID}/media
     multipart: file=@ITRV_109B.pdf, type=application/pdf, messaging_product=whatsapp
  → {"id": "MEDIA_ID"}

POST https://graph.facebook.com/v{N}/{PHONE_NUMBER_ID}/messages
{
  "messaging_product": "whatsapp",
  "to": "91XXXXXXXXXX",
  "type": "template",
  "template": {
    "name": "itr_document",
    "language": {"code": "en"},
    "components": [
      {"type": "header", "parameters": [
        {"type": "document", "document": {"id": "MEDIA_ID", "filename": "ITRV_109B_2024.pdf"}}]},
      {"type": "body", "parameters": [
        {"type": "text", "text": "RAKESH SHARMA"},
        {"type": "text", "text": "ITR-V acknowledgement"},
        {"type": "text", "text": "2024"}]}
    ]
  }
}
  → {"messages": [{"id": "wamid.…"}]}
  5. Results are shown per file: ✓ Accepted or ✗ the reason, with a Retry failed button.
  6. No double-sending: the app remembers, for this run only, which files went to which number. Sending the same file to the same number again requires ticking an extra confirmation.

The sent filename uses the same year-appended name as copying (ITRV_109B_2024.pdf), so the client can tell years apart in their chat. The {{2}} document type is “ITR-V acknowledgement” for ITRV files and “tax computation” for Computation files (wording to be confirmed).

7. Pricing

How Meta charges (from Meta's pricing docs)

  • Per delivered message, by category and recipient country. This model replaced per-conversation pricing on 1 July 2025. Messages from clients to you are free.
  • Template messages (marketing, utility, authentication) are always charged, including utility templates inside the 24-hour window since 1 Oct 2026.
  • Service messages (free-form replies in the 24-hour window): the first 1,000 per phone number per month are free since 1 Oct 2026; after that they are charged.
  • Volume discounts apply to utility and authentication messages once monthly volume is high. They are irrelevant at a CA firm's scale.
  • The API itself is free; there is no monthly fee from Meta. Prices change only on 1 Jan, 1 Apr, 1 Jul or 1 Oct, with notice.

8. Rules, limits & risks

TopicWhat it means for ITR Fetch
Opt-inWhatsApp's business policy requires that recipients have agreed to receive WhatsApp messages from the business. The firm should record each client's consent, for example a line in the engagement letter. ITR Fetch can't check this.
Messaging limitNew accounts can message 250 different numbers outside the 24-hour window per rolling 24 hours, across the whole business portfolio. That is enough for daily use; verify the business before a busy filing season to raise it to 2,000.
Quality ratingIf many clients block or report the number, Meta lowers its quality rating and can restrict it. Sending only expected documents to consenting clients keeps this green. The settings screen shows the rating.
Template reclassificationIf Meta judges the template promotional, it becomes marketing and costs about 7× more. Keep the wording strictly transactional. The app warns if the template's category changes.
Wrong recipientThe biggest real risk is sending a tax return to the wrong person. Mitigations: the number pre-fills from the client's own ITR, a confirmation repeats the number and name, and a number edited by hand gets an extra “I've checked this number” tick.
No delivery confirmationCovered in section 4. The app is honest that “accepted” is not “delivered”.
Token leakageAnyone with the token can message as the firm. It is kept in the OS keychain and can be revoked any time in Meta Business settings → System users.
API version churnGraph API versions are retired about 2 years after release. The version is one constant in the code and needs bumping in a future release.
Billing deadlineIndian businesses must move to INR billing by 31 Dec 2026, or Meta stops delivering messages on 1 Jan 2027.

10. Milestones

  1. Prototype against Meta's test number: a whatsapp.py client (upload, send template, read phone and template status) and a command-line check that sends one PDF to your own phone. This confirms the document-header payload and the certificate handling on the bundled Python.
  2. Phone numbers: extend names.py to read MobileNo and normalise it, with tests.
  3. Secrets and settings: Keychain / Credential Manager storage, and the settings screen with “Test connection”.
  4. Send flow: the send panel, confirmation, per-file results, retry, and the duplicate-send guard.
  5. Hardening: error-message mapping for common API errors (expired token, template not approved, rate limited, number invalid), then a manual run on both Windows and macOS builds.
  6. Optional later: a webhook relay for delivery status.

11. Decisions for you
