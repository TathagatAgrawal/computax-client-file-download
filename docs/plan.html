1. Summary

ITR Fetch is a small local web app. The user opens it like any other app on Windows or macOS; no terminal window appears. It starts a web server on 127.0.0.1 and opens the browser. On first launch, it asks once for the location of the CompuTax folder and remembers it. After that, the user searches for a client by ID or by name, picks the years (a range, separate years, or both) and chooses a destination folder in the operating system's own folder dialog. They click Copy files, and the app copies each year's ITRV_<id>.pdf and Computation_<id>_<year>_<n>.pdf into the destination. It then shows what was found and what was missing.

  • Backend: Python 3.12, standard library only (http.server, pathlib, shutil, json, webbrowser, tkinter for the Windows folder dialog). No third-party runtime packages.
  • Frontend: one HTML page with plain JavaScript and CSS, bundled inside the app. No framework, no CDN, and it works offline.
  • Shipping: PyInstaller builds a windowless ITR Fetch.exe for Windows and a background ITR Fetch.app for macOS in GitHub Actions, both with the ITR Fetch icon. The user installs nothing, not even Python.
  • State: no login, no database and no history. The only thing saved is the CompuTax folder path, in a one-key settings.json in the OS's standard settings folder. Client names are held in memory only and never written to disk.

3. Requirements

Functional

  1. On first launch, ask for the location of the CompuTax folder (via the native folder dialog or a pasted path) and check that it contains year folders. Save it so the prompt is one-time. It can be changed later from the header.
  2. Show every client found in a dropdown, as ID + name. Fuzzy search matches either the ID or the name.
  3. After a client is chosen, show the years that client exists in. The user can select separate years, a range, or both.
  4. Let the user pick the destination folder using the native OS folder dialog.
  5. Copy ITRV_<id>.pdf (plus _Revised) and every Computation_<id>_<year>_<n>.pdf for each selected year into <destination>/<ID>/, appending _<year> to filenames that don't already contain the year.
  6. Show a per-year report (copied, missing, warnings) with an Open folder button.

Non-functional

  • Runs on Windows and macOS. The end user installs no dependencies.
  • Local only: binds to 127.0.0.1 with no network exposure, no login and no telemetry.
  • Never modifies or deletes anything inside CompuTax (read-only).
  • Simple UI: one screen, three inputs, one button.

Lifecycle

  1. Launch. The app runs in the background with no terminal window (windowless on Windows; on macOS an LSUIElement app with no Dock icon). If an instance is already running (recorded in a temporary instance.json and confirmed with /api/ping), it just opens a new browser tab on that instance and exits. Otherwise it finds a free port, generates a random session token, starts the server on 127.0.0.1 and opens http://127.0.0.1:<port>/?t=<token> in the default browser.
  2. Settings. The app reads settings.json for the saved CompuTax path. If the path is missing or no longer valid, the UI shows the one-time setup screen. A --root PATH command-line flag overrides the saved path.
  3. Index. One os.scandir pass over each <root>/<YYYY>/ builds {ID_UPPER: {display_id, years: {year: folder_path}}}. It lists folder names only, so it takes milliseconds for about 2,600 folders.
  4. Names. A background thread then reads one FiledJson per client (the most recent year that has one) and adds the name to the index. This is roughly 413 small JSON reads, under a second on a local disk and a few seconds on a network share. The dropdown works by ID immediately, and names appear as soon as they are loaded. Both the ID index and the names are rebuilt on Rescan.
  5. Per-client detail. When a client is selected, the server lists only that client's year folders. For each year it reports which ITRV and Computation files exist, so the year chips can show availability.
  6. Choose folder. Browse… calls /api/pick-folder. The server opens the native folder dialog and waits, and the request returns the chosen path, or null if the user cancels.
  7. Copy. On submit, the server re-resolves files against the live disk and copies them with shutil.copy2, which keeps timestamps. It returns the per-year report.
  8. Quit. Each open page holds a server-sent-events connection to /api/events. When the last one closes (tab closed, browser quit), the server notices immediately and quits after a 4-second grace period, which lets a page reload reconnect. It never quits while a folder dialog is open. If no page connects within 90 seconds of launch (for example, the browser failed to open), it quits too. The header's Quit link stops it at once. Start-up failures are written to error.log in the settings folder, since there is no console.

Native folder dialog

Browsers cannot reveal a real folder path to a web page, so the dialog is opened by the local Python server, not the browser. The app needs to write several files, so it uses the OS's “choose folder” dialog rather than a per-file “Save As” dialog, which would mean one prompt per PDF. The same dialog is used for the one-time CompuTax setup.

5. File-matching & name rules

For client ID and year Y, the client folder is the one under <root>/Y/ whose name equals ID case-insensitively. Inside it, these case-insensitive full-name regexes apply:

ITRV        ^ITRV_{ID}(_Revised)?\.pdf$
Computation ^Computation_{ID}_{Y}_\d+\.pdf$
FiledJson   ^FiledJson_{ID}_\d+\.json$        (names only)

{ID} is passed through re.escape. ComputationCompare_*, *.pdf_ and every other file are ignored. If a pattern matches nothing but the folder contains an ITRV_*.pdf or Computation_*.pdf for a different ID, the report shows a warning and the file is not copied.

Client name

  • The app uses the most recent year that has a matching FiledJson. If there are several in that year, it uses the highest _n.
  • It finds the first AssesseeName object by walking the JSON, so it works for every ITR form without hard-coded paths. The name is FirstName MiddleName SurNameOrOrgName, with empty parts dropped and spaces collapsed. Firms and companies only fill SurNameOrOrgName.
  • Files are read as utf-8-sig. An unreadable or malformed file is skipped, and the app tries the next older year.
  • If a client's name changed across years, older names are kept as hidden search aliases. Searching the old name still finds the client, but only the latest name is shown.

Output layout

<destination>/
  109B/
    ITRV_109B_2021.pdf
    ITRV_109B_2022.pdf
    ITRV_109B_Revised_2022.pdf
    Computation_109B_2021_1.pdf
    Computation_109B_2022_1.pdf
    Computation_109B_2022_2.pdf

All PDFs for a client go directly into one folder named after the client ID. Because the ITRV filename has no year, _<year> is appended before .pdf to every file whose name doesn't already contain the year, so files from different years can't overwrite each other. Computation files already contain the year and keep their original names. The check ignores the client ID part of the name, so a client whose ID looks like a year still gets the suffix. Existing files are never overwritten: if a file with the same name is already in the destination, it is left unchanged and the report says “already there”. Only missing files are written. If a folder has the same name as a file, that file is not saved and the report shows a warning; the rest of the batch continues.

6. Local HTTP API

All /api/* calls must carry the header X-Session-Token. Requests whose Host is not 127.0.0.1:<port> or localhost:<port> are rejected.

Fuzzy search over ID and name

  • Each client has these search fields: ID, name and old-name aliases. The query is scored against each field, and the best score wins.
  • ID scoring (case-insensitive), best first: exact, then prefix, then substring, then in-order subsequence. Ties go to fewer gaps and the shorter ID.
  • Name scoring is word-aware. Every query word must match a name word by prefix (best), by substring, or by subsequence for typos with missing letters. Word order doesn't matter, so sharma rak and rakesh sh both find RAKESH SHARMA.
  • Ranking: an exact or prefix ID match always ranks above name matches, so typing 42 puts client 42 first even if other names contain “42”. Below that, results are ordered by score.
  • The matched characters are highlighted in whichever field matched. Clients without a name show “(name not found)” in grey and are searchable by ID only.
  • Keys: ↑/↓ to move, Enter to choose, Esc to close. With an empty query, the full list is shown in natural ID order (scrollable).

8. Zero-dependency distribution

The end user downloads one file for their OS from the GitHub Releases page and opens it. The app is called ITR Fetch; its icon (a document with a download arrow on a blue rounded square) is drawn in packaging/icon/icon.svg and converted to .icns, .ico and the page favicon by packaging/icon/build_icons.py.

OSArtifactFirst-run note
Windows 10/11 (x64)ITR-Fetch-Windows.exeSmartScreen warns about an unsigned app: “More info → Run anyway”.
macOS, Apple Silicon (M1 and later)ITR-Fetch-macOS.zip containing ITR Fetch.appGatekeeper blocks unsigned apps the first time: System Settings → Privacy & Security → “Open Anyway”. Signing and notarisation would need an Apple Developer account ($99/yr).
  • The build runs in .github/workflows/release.yml, triggered by pushing a v* tag. A matrix of windows-latest and macos-latest (arm64) runs uv sync then uv run pyinstaller packaging/itr-fetch.spec (one file, with static/ bundled). The binaries are attached to the release.
  • PyInstaller is a dev dependency only (uv add --dev pyinstaller). The shipped app has zero third-party runtime packages. On Windows, PyInstaller bundles Tcl/Tk automatically for the folder dialog. On macOS, Tk is excluded because the dialog uses osascript.
  • Developers can still run it with uv run computax-client-file-download [--root PATH] [--port N] [--no-browser]. That also works on Linux, but Linux is not a supported target and has no built binary.
  • The repo is private, so whoever downloads releases needs access to it. Alternatively, you can share the binaries directly (for example by email or a shared drive).

10. Safety & edge cases

  • Network: the server binds only to 127.0.0.1, so other machines cannot reach it.
  • Other local web pages: a random per-launch token plus a check of the Host header block another browser tab or a DNS-rebinding attack from calling the API, reading client names or copying tax files.
  • Client names (personal data) live only in server memory and the open page. They are never logged or written to disk.
  • Path handling: client IDs and years must exist in the index and are never used as raw path fragments. Source paths are resolved and must stay under the CompuTax root. Dialog prompt strings are fixed in code and passed to osascript as arguments, never built from user input.
  • Read-only source: the code never opens anything under the root for writing.
  • Destination errors (folder missing, no permission, disk full, file locked on Windows) are reported for each file and do not abort the whole batch.
  • Dialog hidden behind other windows: the Windows dialog is forced on top, and the macOS dialog is attached to the frontmost app. If the dialog is still lost, the page message says to look for it. The user can also cancel it from the page, which ends the child process.
  • Network drives: if CompuTax sits on a NAS or SMB share, scanning stays fast because only folder names are listed. Names load in the background. Copies may be slower; the button shows a spinner and the files copied so far.
  • Port in use: the app asks the OS for a free port. Two copies can run side by side.
  • Missing or moved CompuTax folder (for example a drive letter changed): the app goes back to the setup screen with the old path pre-filled.

11. Testing

  • Unit tests (pytest) run against a synthetic tree that reproduces every quirk from section 2: mixed case, _Revised, _2/_3, ComputationCompare, .pdf_, the misfiled 264B-style folder, empty folders, and the 2012-style single-file year.
  • Name tests: FiledJson fixtures for ITR-1 through ITR-6, BOM-prefixed and malformed files, a name change across years (alias), and a misfiled folder that must not take another client's name.
  • API tests: start the server on a random port and exercise every endpoint, including token rejection and path-traversal attempts. The folder dialog is replaced with a stub.
  • Fuzzy search: a table of query → expected-top-result cases covering ID and name matches, run in Node in CI.
  • Manual check against the real data: run with --root ~/projects/CompuTax, spot-check about 10 clients across years against Finder, and check the folder dialog by hand on both a Mac and a Windows PC.
  • CI: pytest runs on Windows and macOS to catch path and case-sensitivity differences.
