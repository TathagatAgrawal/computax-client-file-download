1. Summary

A small local web app. The user double-clicks one executable (Windows, macOS or Linux). It starts a web server on 127.0.0.1 and opens the browser. On first launch, it asks once for the location of the CompuTax folder. After that, the user picks a client ID from a fuzzy-search dropdown, picks the years (a range, separate years, or both) and picks a destination folder. They click Copy files, and the app copies each year's ITRV_<id>.pdf and Computation_<id>_<year>_<n>.pdf into the destination. It then shows what was found and what was missing.

  • Backend: Python 3.12, standard library only (http.server, pathlib, shutil, json, webbrowser). No third-party runtime packages.
  • Frontend: one HTML page with plain JavaScript and CSS, bundled inside the app. No framework, no CDN, and it works offline.
  • Shipping: PyInstaller builds a single-file executable per OS in GitHub Actions. The user installs nothing, not even Python.
  • State: no login, no database and no history. The only thing saved is the CompuTax folder path, so the app asks for it just once (see decision 1).

3. Requirements

Functional

  1. On first launch, ask for the location of the CompuTax folder and check that it contains year folders. Remember it so the prompt is one-time. It can be changed later from the header.
  2. Show every client ID found in the folder in a dropdown with fuzzy matching.
  3. After an ID is chosen, show the years that ID exists in. The user can select separate years, a range, or both.
  4. Let the user pick the destination folder.
  5. Copy ITRV_<id>.pdf (plus _Revised) and every Computation_<id>_<year>_<n>.pdf for each selected year.
  6. Show a per-year report (copied, missing, warnings) with an Open folder button.

Non-functional

  • Runs on Windows, macOS and Linux. The end user installs no dependencies.
  • Local only: binds to 127.0.0.1 with no network exposure, no login and no telemetry.
  • Never modifies or deletes anything inside CompuTax (read-only).
  • Simple UI: one screen, three inputs, one button.

Lifecycle

  1. Launch. The executable finds a free port and generates a random session token. It starts the server on 127.0.0.1 and opens http://127.0.0.1:<port>/?t=<token> in the default browser. A small console window shows the URL and says “close this window to quit”.
  2. Settings. The app reads settings.json for the saved CompuTax path. If the path is missing or no longer valid, the UI shows the one-time setup screen. A --root PATH command-line flag overrides the saved path.
  3. Index. One os.scandir pass over each <root>/<YYYY>/ builds {ID_UPPER: {display_id, years: {year: folder_path}}}. It lists folder names only and does not read any files, so it takes milliseconds for about 2,600 folders. The index is kept in memory and rebuilt on Rescan.
  4. Per-client detail. When an ID is selected, the server lists only that client's year folders. For each year it reports which ITRV and Computation files exist, so the year chips can show availability.
  5. Copy. On submit, the server re-resolves files against the live disk and copies them with shutil.copy2, which keeps timestamps. It returns the per-year report.
  6. Quit. The user clicks Quit in the header or closes the console window. The browser sends a heartbeat every 15 seconds. If no heartbeat arrives for about 2 minutes, the server exits by itself, so no orphan process is left behind.

5. File-matching rules

For client ID and year Y, the client folder is the one under <root>/Y/ whose name equals ID case-insensitively. Inside it, these case-insensitive full-name regexes apply:

ITRV        ^ITRV_{ID}(_Revised)?\.pdf$
Computation ^Computation_{ID}_{Y}_\d+\.pdf$

{ID} is passed through re.escape. ComputationCompare_*, *.pdf_ and every other file are ignored. If a pattern matches nothing but the folder contains an ITRV_*.pdf or Computation_*.pdf for a different ID, the report shows a warning and the file is not copied.

Output layout

Recommended layout (decision 2):

<destination>/
  264A/
    AY2021/  ITRV_264A.pdf   Computation_264A_2021_1.pdf
    AY2022/  ITRV_264A.pdf   Computation_264A_2022_1.pdf
    AY2023/  ...

Original filenames are kept. The ITRV filename contains no year, so year subfolders prevent files from different years overwriting each other. If a file with the same name already exists in the destination, the app skips it when its size and modification time are identical, and otherwise overwrites it. Each case appears in the report.

6. Local HTTP API

All /api/* calls must carry the header X-Session-Token. Requests whose Host is not 127.0.0.1:<port> or localhost:<port> are rejected.

Method & pathBody / queryReturns
GET /?t=tokenThe app page. The token is passed to JS.
GET /api/settings—{root, root_valid}
PUT /api/settings{root}Validates (at least one YYYY subfolder containing client folders), saves and rebuilds the index. Returns {root, years, client_count} or a 400 with the reason.
GET /api/clients—[{id, years:[2020,…]}], sorted naturally (1, 2, 10, 103A…)
POST /api/rescan—Rebuilds the index. Returns the same shape as /api/clients.
GET /api/clients/{id}—{id, years:{2021:{itrv:[…], computation:[…], warnings:[…]}, …}}
GET /api/browse?path= (empty = home){path, parent, dirs:[…], shortcuts:[Home, Desktop, Documents, Downloads, drives…]}
POST /api/mkdir{parent, name}Creates a folder from the picker's “New folder” button.
POST /api/copy{id, years:[…], dest}{dest_root, years:[{year, copied:[…], skipped:[…], missing:[…], warnings:[…]}], totals}
POST /api/open{path}Opens the folder in Finder, Explorer or the Linux file manager (open / os.startfile / xdg-open).
POST /api/heartbeat, POST /api/quit—Liveness check and shutdown.

Fuzzy matching behaviour

  • Case-insensitive. Results are ranked: exact match, then prefix, then substring, then in-order subsequence. Ties are broken by fewer gaps and shorter ID. Matched characters are highlighted.
  • Examples: 109b → 109B, 109B1; neha → NEHA1…NEHA5; 7d → 7D first.
  • Keys: ↑/↓ to move, Enter to choose, Esc to close. With an empty query, the full list is shown in natural order (scrollable).
  • Optional extra (decision 4): show the assessee's name next to the ID and make it searchable. The name would be read from FiledJson_*.json, which exists for about 88% of client-years.

8. Zero-dependency distribution

The end user downloads one file for their OS from the GitHub Releases page and runs it.

OSArtifactFirst-run note
Windows 10/11computax-downloader-windows.exeSmartScreen warns about an unsigned app: “More info → Run anyway”.
macOS (Apple Silicon + Intel)computax-downloader-macos-arm64, …-x86_64Gatekeeper blocks unsigned apps the first time: right-click → Open, or run xattr -d com.apple.quarantine. Signing and notarisation would need an Apple Developer account ($99/yr).
Linux x86_64computax-downloader-linuxchmod +x after download.
  • The build runs in .github/workflows/release.yml. A matrix of windows-latest, macos-14 (arm64), macos-13 (x86_64) and ubuntu-22.04 runs uv sync then uv run pyinstaller --onefile --add-data static, triggered by pushing a v* tag. Ubuntu 22.04 keeps glibc old enough for most distros.
  • PyInstaller is a dev dependency only (uv add --dev pyinstaller). The shipped app has zero third-party runtime packages.
  • Developers can still run it with uv run computax-client-file-download [--root PATH] [--port N] [--no-browser].
  • Note: the repo is private, so whoever downloads releases needs access to it. Alternatively, you can share the binaries directly (for example by email or a shared drive).

10. Safety & edge cases

  • Network: the server binds only to 127.0.0.1, so other machines cannot reach it.
  • Other local web pages: a random per-launch token plus a check of the Host header block another browser tab or a DNS-rebinding attack from calling the API and copying tax files.
  • Path handling: client IDs and years must exist in the index and are never used as raw path fragments. Source paths are resolved and must stay under the CompuTax root.
  • Read-only source: the code never opens anything under the root for writing.
  • Destination errors (folder missing, no permission, disk full, file locked on Windows) are reported for each file and do not abort the whole batch.
  • Network drives: if CompuTax sits on a NAS or SMB share, scanning stays fast because only folder names are listed. Copies may be slower; the button shows a spinner and the files copied so far.
  • Port in use: the app asks the OS for a free port. Two copies can run side by side.
  • Missing or moved CompuTax folder (for example a drive letter changed): the app goes back to the setup screen with the old path pre-filled.

11. Testing

  • Unit tests (pytest) run against a synthetic tree that reproduces every quirk from section 2: mixed case, _Revised, _2/_3, ComputationCompare, .pdf_, the misfiled 264B-style folder, empty folders, and the 2012-style single-file year.
  • API tests: start the server on a random port and exercise every endpoint, including token rejection and path-traversal attempts.
  • Fuzzy matcher: a small set of query → expected-top-result cases, run in Node by CI or in a browser test page.
  • Manual check against the real data: run with --root ~/projects/CompuTax and spot-check about 10 clients across years against Finder.
  • CI: pytest runs on Windows, macOS and Linux to catch path and case-sensitivity differences.
